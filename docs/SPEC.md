# СОСТАВ ЗАЯВКИ — спецификация мини-приложения

Единственный источник правды по содержанию и оформлению. Копирайт здесь —
канон: переписывать формулировки нельзя, можно только переносить их в код.

Эта версия полностью заменяет прежнюю воронку-расследование «Дело Васи»
(архив: `docs/ARCHIVE-delo-vasi-spec.md`). Старая структура, её грамматика и
её копирайт не переиспользуются нигде.

## 1. Что это

Telegram Mini App. Компактная воронка на 14 экранов вокруг трёх видео,
ведущая к практикуму «Лендос за вечер» за 3 990 ₽.

**Вся логика в одной строке:**

- Видео 1: ты неправильно смотрел на целевой трафик.
- Видео 2: ты неправильно думал, что хорошей настройки достаточно.
- Видео 3: ты неправильно считал, что посадочная — не твоя проблема.

**Герой — сам зритель.** Отдельного персонажа-специалиста нет. Вася, Стёпа,
Коля, Саша и Федя — пятеро покупателей ремонта внутри примера, не более того.

**Что человек должен вынести:**

> Раньше я контролировал маленький кусок системы, но отвечал за весь
> результат. Теперь я могу забрать под контроль человека, предложение и
> посадочную.

**Путь до предложения:** около 30 минут.

## 2. Дизайн-система

### 2.1 Мир

Промышленная лаборатория, 70%. Современное расследование, 30%.

Не пробирки, черепа и химическая посуда — это костюм. Берём то, как выглядит
производство, где важна чистота партии: маркировка образцов, номера партий,
предупреждающая штриховка, ярлыки, утилитарная типографика. От расследования
остаются связи и всплывающие мысли поверх изображения — там, где нужно
показать, что логика оборвалась.

**Несущая метафора — чистота.** Целевой трафик это сырьё, а не продукт.
Заявка чиста настолько, насколько чисты четыре компонента: человек, причина
покупки, оффер, посадочная. Один грязный компонент портит партию.

Исключение: экран 0 не принадлежит этому миру. Он должен выглядеть настоящим
Telegram-чатом, а не стилизацией (см. §4, экран 0).

### 2.2 Цвет

| Токен | Значение | Роль |
|---|---|---|
| `--ink-900` | `#0D1218` | графитовый фон приложения |
| `--ink-800` | `#101922` | приподнятая поверхность, карточки |
| `--ink-700` | `#15212D` | вторая ступень: пузыри чата, панели |
| `--ink-600` | `#1E2C3A` | декоративные разделители |
| `--edge` | `#405568` | границы интерактивных элементов, ≥2.2:1 к фону |
| `--fog` | `#8D9AA6` | второстепенный текст |
| `--paper` | `#F2F4F5` | основной текст |
| `--toxic` | `#E4D43A` | **основной акцент**: маркировка, партия, арсенал, разблокировка, цена |
| `--lab` | `#86B08F` | чисто/верно/подтверждено: верный ответ, зафиксированный выбор, заполненный арсенал |
| `--signal` | `#67D5FF` | выбранное состояние интерактивных элементов |
| `--alarm` | `#E44C4C` | опасность |

**Дисциплина акцентов.** Жёлтый — рабочий цвет мира, а не редкость: им
маркируется всё служебное. Зелёный означает ровно одно: компонент чист.
Красный допустим в трёх местах: обвинение «Во всём виноват ты» (экран 0),
смерть логики после клика (10), потеря жизни в квизе (9). Синий — только
текущее выделение выбора, ничего больше.

Предупреждающая штриховка: `repeating-linear-gradient` 45°, `--toxic` и
`--ink-900`, шаг 10px. Применяется узкой полосой-разделителем на границах
разделов и над ценой. Не как фон блока с текстом — иначе текст не прочитать.

Тема принудительно тёмная. Тема клиента Telegram игнорируется.

### 2.3 Типографика

Три вариативные гарнитуры из `@fontsource-variable`, все с кириллицей,
самохост, без внешних запросов. Рукописная гарнитура прежней версии удаляется.

| Роль | Гарнитура | Применение |
|---|---|---|
| Display | Oswald Variable | заголовки экранов, крупные удары, `uppercase` |
| Body | Onest Variable | весь читаемый текст, кнопки, варианты, чат |
| Mono | JetBrains Mono Variable | маркировка: `ЧАСТЬ 01 / 03`, `АРСЕНАЛ`, время в чате, кодовые слова |

Шкала (`rem`): 0.75 / 0.8125 / 0.875 / 1 / 1.125 / 1.375 / 1.75 / 2.25 / 3.
Тело — 1rem, интерлиньяж 1.55. Строка не шире 34 символов на мобильном.

### 2.4 Пространство и форма

Шаг сетки 4px. Поля экрана 20px. Ритм между блоками 24px, между смысловыми
группами 40px. Радиусы: 4px у меток, 12px у карточек, 999px у чипов, 18px у
пузырей чата. Теней нет: глубина строится слоями фона и границами.

### 2.5 Движение

Библиотека `motion`. Анимируются `transform` и `opacity`.

- Смена состояния: 150–200 мс, `var(--ease-out)`.
- Появление: пружина `{ stiffness: 400, damping: 32 }`, никогда не из `scale(0)`.
- Каскад списка: 40 мс на элемент, максимум 6.
- Сюжетные сцены (лента чата, разрыв связки) — до 3 с.
- `prefers-reduced-motion: reduce`: убираются сдвиги, масштаб, повороты и
  тряска; переходы прозрачности остаются.
- Haptic: `select` на каждый выбор, `success` на разблокировку и верный ответ,
  `error` на потерю жизни, `heavy` на обвинение и на разрыв связки.

## 4. Содержание экранов

Канонический текст. Пунктуация и мат сохраняются дословно.

### Экран 0 — `prologue-chat`

**Это не стилизация под чат. Это должно выглядеть настоящим Telegram.**
Человек первые секунды не должен понимать, что открыл приложение.

Требования к достоверности:
- Круглый аватар с инициалом слева от имени.
- Имя **Алексей**, ниже подпись `клиент`.
- Статус `печатает...` в шапке, пока идёт лента.
- Входящие пузыри прижаты влево, фон `--ink-700`, радиус 18px; у последнего
  пузыря подряд идущей группы нижний левый угол срезан до 4px.
- Время `ЧЧ:ММ` моноширинным в правом нижнем углу каждого пузыря, цвет `--fog`.
  Время возрастает с шагом в минуту и отсчитывается от текущего момента назад
  на длину ленты — чтобы не выглядело фиксированной подделкой.
- Галочек прочтения нет: все сообщения входящие.
- Фон ленты чуть отличается от фона приложения.

**Сообщения не удаляются.** Они приходят одно за другим и накапливаются.
Когда лента перестаёт помещаться, она уезжает вверх сама, прижимая последнее
сообщение к низу, как в настоящем мессенджере.

Порядок ленты (интервал 900 мс):

1. `Слушай, заявки какие-то говно.`
2. `Лиды холодные.`
3. `Не, они вообще ледяные.`
4. `Отдел продаж не может их закрыть.`
5. `Люди только цену спрашивают и уходят.`
6. `Продаж нет.`

Дальше быстрее (интервал 350 мс):

7. `Директ не работает.`
8. `Авито не работает.`
9. `ВК не работает.`
10. `Мы просто сливаем бюджет.`
11. `Раньше заявки были лучше.`
12. `Наверное, ты что-то неправильно настроил.`

Пауза 1200 мс, статус `печатает...` держится заметно дольше обычного. Затем
последнее сообщение — крупнее остальных, цвет `--alarm`:

> **Во всём виноват ты.**

В момент его появления экран коротко дёргается (два колебания по 4px, 180 мс),
фон на 400 мс уходит в красноватый и возвращается. При
`prefers-reduced-motion` тряски и вспышки нет, сообщение просто появляется.

Ленту можно пропустить тапом. Через 3 с появляется тихая подсказка:
`Тапни, чтобы пропустить`.

После обвинения статус `печатает...` гаснет и появляется вопрос уже от
приложения — визуально отделённый от чата, это первый момент, когда человек
понимает, что он в приложении:

> **Знакомая ситуация?**

Основная кнопка: **Да, было такое**
Второстепенная, мельче: `Нет, мои клиенты никогда так не пишут`

При нажатии второстепенной — реплика, затем тот же переход дальше:

> Ну да, конечно. Ладно, проходи.

### Экран 9 — `quiz`

Заголовок: **ТЫ РЕАЛЬНО РАЗОБРАЛСЯ?**
Подпись: `Пять ситуаций. Три жизни.`

Счётчик жизней — три деления. Потерянное гаснет и краснеет.

Неверный ответ: минус жизнь, показывается разбор, дальше следующий вопрос.
Верный ответ: разбор тоже показывается, жизнь не тратится.
Жизни кончились — квиз начинается заново с первого вопроса, жизни
восстанавливаются, и экран честно об этом говорит:
`Жизни кончились. Разбор ты видел — попробуй ещё раз.`

Пять вопросов. Верный вариант помечается флагом в данных, а не позицией;
порядок вариантов на экране фиксирован, как записан здесь.

> ПРАВКА (координатор, ревизия задачи 3): `Разбор:` ниже — подпись-метка
> этого документа, не часть фразы; в интерфейсе она выводится отдельным
> элементом верстки. Из-за этого первая буква текста разбора у вопросов 2, 3
> и 5 была случайно записана строчной (как продолжение фразы «Разбор:
> ...») — исправлено на заглавную в вопросах 2, 3 и 5 ниже. Это правка
> разметки документа, а не изменение формулировки.

**1. Какой оффер лучше подходит Васе?**
- Эксклюзивный дизайн-проект от ведущих архитекторов
- Ремонт новостройки в срок, зафиксированный в договоре. За каждый день просрочки — пеня ✓
- Скидка 20% на ремонт до конца месяца
- Ремонт под ключ любой сложности

Разбор: Вася платит аренду и ипотеку одновременно. Каждый месяц просрочки
стоит ему живых денег, поэтому он покупает срок и ответственность за него, а
не дизайн и не скидку. Пеня здесь — доказательство того, что срок настоящий.

**2. Почему Федя может быть целевой заявкой, но не продажей?**
- Он не искал ремонт
- Он не понял объявление
- Ремонт ему нужен, но вкладывать серьёзные деньги в квартиру под снос незачем ✓
- У него нет денег

Разбор: Целевой человек и готовый купить — не одно и то же. У Феди сильная
боль и настоящая потребность, но нет достаточной причины вложить серьёзные
деньги. Клик целевой, заявка целевая, продажи нет.

**3. Что является доказательством, а не обещанием?**
- Работаем на результат
- Гарантируем качество
- Вот три объекта: обещали 60 дней, сдали за 58, 61 и 60 ✓
- Индивидуальный подход к каждому клиенту

Разбор: Обещание говорит, что будет. Доказательство показывает, что уже было,
и его можно проверить. Числа, объекты, сроки и имена — доказательства.

## 5. Заглушки

### 5.1 Видео

> ПРАВКА (координатор, ревизия задачи 3): было три переменные
> (`VITE_VIDEO_1_URL` / `_2_URL` / `_3_URL`, одна на `part={1|2|3}`). Дефект:
> экраны 2 и 4 — это два РАЗНЫХ куска записи видео 1 (до и после
> интерактивной паузы экрана 3, см. экран 3 выше), а не один файл — общая
> переменная заставляла человека, только что выбравшего покупателя, увидеть
> то же видео с начала. Видео 1 разрезано на две переменные; видео 2 и 3 —
> без изменений.

Источники — четыре переменные:

| Переменная | Экран |
|---|---|
| `VITE_VIDEO_1A_URL` | 2 (`v1-part1`), до интерактивной паузы экрана 3 |
| `VITE_VIDEO_1B_URL` | 4 (`v1-part2`), разбор после паузы |
| `VITE_VIDEO_2_URL` | 7 (`v2`) |
| `VITE_VIDEO_3_URL` | 11 (`v3`) |

Переменная задана → `<video controls playsinline preload="metadata">`.
Переменная пуста → заглушка 16:9: фон `--ink-800`, граница `--ink-600`, по
центру моноширинная метка `ВИДЕО · ЧАСТЬ 0N`, ниже `материал ещё не подшит`.
Никаких фейковых кнопок воспроизведения.

**Кодовое слово на заглушке.** Пока видео `1A`/`1B` (часть 1) или видео `2`
(часть 2) не подключено, под заглушкой соответствующего экрана служебной
пометкой цветом `--fog` выводится слово, которое понадобится дальше:
`Кодовое слово этой части: ФОРМУЛА` — под ОБЕИМИ половинами видео 1 (экраны 2
и 4: слово привязано к видео 1 целиком, а не к конкретной половине) и
`ОФФЕР` — под видео 2 (экран 7). Как только соответствующая переменная с
видео заполнена, её пометка исчезает сама, без правки кода. Слот видео
никогда не блокирует переход дальше.

## 6. Состояние

`src/store/funnel.ts`, zustand с `persist`, ключ `sostav-zayavki-v1`.

```ts
interface FunnelData {
  step: number;              // 0..13
  maxStep: number;
  tool: string | null;       // экран 1
  castPick: string | null;   // экран 3
  siteAnswer: string | null; // экран 6
  unlocked: string[];        // 'audience' | 'offer'
  quizIndex: number;         // 0..5
  quizLives: number;         // 0..3
  quizDone: boolean;
  objectionsSeen: string[];  // экран 13
}
```

Действия: `goNext`, `goBack`, `setTool`, `setCastPick`, `setSiteAnswer`,
`unlock(id)`, `answerQuiz(correct)`, `resetQuiz`, `seeObjection(id)`, `reset`.

Правила: `goNext` не выходит за границу маршрута; `maxStep` только растёт;
содержимое `localStorage` валидируется поштучно — испорченное поле заменяется
начальным значением, остальные сохранившиеся ответы уцелевают; приложение не
имеет права показать белый экран ни при каком содержимом хранилища.
