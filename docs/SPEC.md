# КТО УБИЛ ПРОДАЖУ? — спецификация мини-приложения

Единственный источник правды по содержанию и оформлению. Копирайт здесь —
канон: переписывать формулировки нельзя, можно только переносить их в код.

---

## 1. Что это

Telegram Mini App. Воронка-расследование для специалистов по трафику.
Пользователь проходит 24 экрана и в конце отвечает на тот же вопрос, что и в
начале, — и видит, что ответил иначе.

**Герой:** Вася — нормальный специалист по рекламе 28–35 лет. Не новичок, не
карикатура. Он уже сделал всё, что умеет, а продаж нет.

**Обещание:** за три шага разобраться, где нормальный трафик превращается в
говно-лиды, и увидеть, какие части связки можно забрать под контроль.

**Мир:** современное цифровое расследование. 70% «Шерлок» (доска улик,
всплывающие мысли, связи, реконструкция), 30% «Во все тяжкие» (трансформация
обычного человека, лабораторная метафора связки, токсичный жёлтый акцент).
Никаких прямых отсылок к сериалам, персонажам и атрибутике.

## 2. Дизайн-система

### 2.1 Цвет

Токены объявляются в `src/styles/tokens.css` как CSS-переменные и
подключаются в Tailwind 4 через `@theme`.

| Токен | Значение | Роль |
|---|---|---|
| `--ink-900` | `#0D1218` | графитовый фон приложения |
| `--ink-800` | `#101922` | приподнятая поверхность, карточки |
| `--ink-700` | `#15212D` | холодная тёмно-синяя панель, досье |
| `--ink-600` | `#1E2C3A` | границы, разделители, волосяные линии — **только неинтерактивных** блоков |
| `--edge` | `#405568` | граница **интерактивных** элементов (Choice, ghost-кнопка, DossierCard) |
| `--fog` | `#8D9AA6` | второстепенный текст, подписи |
| `--paper` | `#F2F4F5` | основной текст |
| `--signal` | `#67D5FF` | новое понимание, вывод, ссылки, активное состояние |
| `--evidence` | `#E4D43A` | найденная улика, стикер, разблокировка |
| `--alarm` | `#E44C4C` | обвинение и потерянная продажа |

**Дисциплина акцентов.** Красный допустим ровно в пяти местах: сообщение
«Во всём виноват ты» (экраны 0 и 21), метка «СКОЛЬЗКОЕ ПРЕДЛОЖЕНИЕ» (12),
«ЛОГИКА ПОТЕРЯНА ПОСЛЕ КЛИКА» (17), досье Феди (8), внутренняя мысль Васи
«Блядь.» (15). Больше нигде. Жёлтый — только улики, стикеры и разблокировки.
Голубой — выводы и интерактивные элементы. Тёплый красный отблеск телефона в
`VasyaScene variant="defeated"` (§2.5) — это освещение сцены, а не
типографический акцент, и в этот список не входит.

Тема принудительно тёмная. Тема клиента Telegram игнорируется.

*(Правка после ревью задачи 2: заведён `--edge`. `--ink-600` на `--ink-900`
даёт контраст 1.32:1 — это не тонкая линия, а фактическое отсутствие границы;
на интерактивных элементах (варианты выбора, ghost-кнопка, карточка досье)
это читалось как текст без всякого признака нажимаемости. `--edge` даёт
2.43:1 к `--ink-900` и 2.30:1 к `--ink-800` — расчёт в отчёте задачи 2.
`--ink-600` остаётся как было — для разделителей и рамок неинтерактивных
блоков, где слабая линия уместна.)*

*(Правка после сквозной починки: список красного был внутренне противоречив —
здесь было заявлено «ровно четыре места», а §4 экран 15 уже требовал мысль
Васи «Блядь.» цветом `--alarm`, и контент-слой (`src/content/bridges.ts`) уже
хранил её именно так. Пятое место реально и оправдано — это эмоциональное дно
воронки, единственная точка, где герой не держит лицо даже перед собой.
Список выше приведён в соответствие с §4 и с уже написанным кодом; текст §4 и
контент не менялись. Тёплый отблеск телефона в `defeated`, как и раньше, в
перечень не входит — это освещение сцены, а не типографический акцент.)*

### 2.2 Типографика

Все шрифты — вариативные, из `@fontsource-variable`, с кириллицей.
Самохост, никаких внешних запросов.

| Роль | Гарнитура | Применение |
|---|---|---|
| Display | Oswald Variable | заголовки дела и актов, крупные обвинения. `uppercase`, `letter-spacing: 0.01em` |
| Body | Onest Variable | весь читаемый текст, кнопки, варианты ответов |
| Mono | JetBrains Mono Variable | системные метки: `ДЕЛО ОТКРЫТО`, `УЛИКА 02 / 03`, таймкоды, номера |
| Hand | Caveat Variable | стикеры-улики и рукописные пометки на полях |

Шкала (мобильный первым, `rem`): 0.75 / 0.8125 / 0.875 / 1 / 1.125 / 1.375 /
1.75 / 2.25 / 3. Заголовок дела — 3rem с `line-height: 0.95`. Тело — 1rem с
`line-height: 1.55`. Строка не шире 34 символов на мобильном.

### 2.3 Пространство и форма

Шаг сетки 4px. Внешние поля экрана — 20px. Вертикальный ритм между блоками —
24px, между смысловыми группами — 40px. Радиус: 4px у системных меток, 12px у
карточек, 999px у чипов. Тени не используются — глубина строится слоями фона
и волосяными границами: `--ink-600` — у неинтерактивных разделителей и рамок,
`--edge` — у границы интерактивных элементов (§2.1).

*(Правка после ревью задачи 2: без различения `--ink-600`/`--edge` граница
у нажимаемых элементов физически не видна на телефоне вечером — контраст к
`--ink-900` всего 1.32:1. Расчёт и объяснение — в §2.1.)*

Стикер-улика: фон `--evidence`, текст `--ink-900`, шрифт Hand, поворот
−2°…+2° (детерминированный от индекса, не случайный при каждом рендере).

### 2.4 Движение

Библиотека `motion`. Анимируются только `transform` и `opacity`.

- Смена состояния (нажатие, выбор, раскрытие): 150–200 мс, `ease-out`.
- Появление элемента: пружина `{ stiffness: 400, damping: 32 }`.
- Появление списка: каскад по 40 мс на элемент, максимум 6 элементов.
- Сюжетные сцены (реел чата, распад сообщения, стирание мысли) — до 3 с,
  это единственное исключение из потолка 600 мс.
- `prefers-reduced-motion: reduce` — декоративное движение выключается
  полностью, элементы появляются сразу в конечном состоянии; сюжетные сцены
  сохраняют последовательность и тайминг, но без сдвигов и масштабирования.
- Haptic Telegram на каждый выбор (`selectionChanged`), на найденную улику
  (`notificationOccurred('success')`), на обвинение (`impactOccurred('heavy')`).

### 2.5 Вася

Изображений персонажа нет. Вася существует как слоистая CSS/SVG-сцена
`<VasyaScene variant=… />` — комната, вид со спины: тёмный стол на переднем
плане, силуэт головы и плеч (без видимой шеи — со спины она не нужна) в
среднем плане, 2–3 монитора со свечением на заднем плане. Свет идёт ОТ
мониторов НА фигуру, поэтому силуэт темнее окружения (контровой свет), а не
светлее — фигуру узнают по контексту комнаты, а не по проработке контура.
Поверх сцены — всплывающие мысли и стикеры.

Варианты различаются содержимым мониторов и позой, а не перекраской фона:
`defeated` (пролог, мониторы тусклые, тёплый отблеск телефона со стола, плечи
опущены, голова наклонена вниз), `searching` (акты 2–3, на одном мониторе —
доска улик: точки и связи, поза собраннее), `assembling` (акт 4, на мониторе —
блок-схема связки, плечо приподнято — угадывается рука, поднятая к экрану),
`control` (финал, все мониторы светятся ровно и холодно-голубым, фигура по
центру, прямая осанка).

Компонент обязан принимать проп `frameSrc?: string`. Если он передан —
рисуется изображение вместо CSS-сцены, вся остальная композиция (мысли,
стикеры, подписи) не меняется. Это слот под будущие кадры.

*(Правка после ревью задачи 2: первая версия рисовала фигуру Васи в пустоте —
светлый силуэт на тёмном фоне, различимый только собственным контуром.
Читалась как шахматная пешка, не как человек. Новая постановка — не
«нарисовать человека», а посадить силуэт в комнату перед мониторами: контекст
несёт узнавание, а не анатомическая точность контура. Ключевой сдвиг —
источник света за спиной фигуры, а не подсветка самой фигуры.)*

## 4. Содержание экранов

Ниже — канонический текст. Пунктуация и мат сохраняются дословно.

### Экран 0 — `prologue-chat`

Шапка чата: **Алексей** · подпись `Клиент`. Статус под именем: `печатает...`

Реел. Каждое сообщение появляется, держится, затем удаляется (сжимается и
гаснет) перед появлением следующего:

1. `Слушай, заявки какие-то говно.`
2. `Лиды холодные.`
3. `Нет, они вообще ледяные.`
4. `Отдел продаж не может их закрыть.`
5. `Люди только спрашивают цену и уходят.`
6. `Продаж нет.`

Затем быстрой очередью, все разом на экране:

- `Директ не работает.`
- `Авито не работает.`
- `ВК не работает.`
- `Мы просто сливаем бюджет.`
- `Видимо, что-то неправильно настроено.`

Все удаляются. Пауза 1,2 с. Статус `печатает...`. Затем крупное последнее
сообщение во всю ширину, цвет `--alarm`:

> **Во всём виноват ты.**

Под чатом: `Знакомая ситуация?`
Кнопка: **Да, было такое**

Тайминги: 900 мс на сообщение, 350 мс на удаление, очередь по 250 мс,
пауза 1200 мс, обвинение появляется за 600 мс с лёгким масштабом.
Реел можно пропустить тапом по экрану — тогда он мгновенно доигрывается до
обвинения.

### Экран 1 — `case-open`

Экран затемняется. Моноширинным, по одной строке:

```
ДЕЛО ОТКРЫТО
```

Затем заголовок Display во всю ширину:

# КТО УБИЛ ПРОДАЖУ?

Подзаголовок:
`Расследование о том, где нормальный трафик превращается в говно-лиды.`

Карточка досье:
`Главный специалист по делу: Вася`
`Статус: не понимает, что происходит`

Кнопка: **К материалам дела**

### Экран 2 — `vasya-intro`

Сцена `VasyaScene variant="defeated"`.

Текст:

> Это Вася.
>
> И он, так же как и ты, хочет понять, какого хрена клиент говорит, что лиды
> говно, если со стороны рекламы всё выглядит нормально.

Список фактов дела (моноширинные маркеры, каскад):

- Поисковый запрос целевой.
- Объявление соответствует запросу.
- Мусора почти нет.
- Человек оставил заявку.
- Менеджер разговаривал с ним пять минут.
- В CRM нет нормальной причины отказа.
- Но продажи всё равно нет.

Реплика клиента (стиль пузыря чата):
> «Лид некачественный».

Мысль Васи (стиль внутренней мысли, курсив, `--fog`):
> «А что именно здесь было некачественным?»

Чипы-версии, появляются каскадом, каждый со знаком вопроса:
`Запрос?` `Объявление?` `Человек?` `Сайт?` `Разговор менеджера?` `Продукт?` `Цена?`

> Или клиент просто решил назвать плохим лидом любого человека, который не
> купил с первого звонка?
>
> Вася не хочет каждый месяц оправдываться и доказывать, что он не виноват.
>
> Он хочет понимать, где реально умерла продажа и что из этого он способен
> исправить.

Кнопка: **Выдвинуть версию**

### Экран 3 — `verdict-first`

Заголовок: **Что бы ты проверил первым?**

Один вариант из шести:

1. Ещё раз поисковые запросы
2. Объявления и ставки
3. Аудиторию и причину покупки
4. Оффер и сайт
5. Работу менеджера
6. Пока вообще непонятно

Оценки не даём ни в каком виде: ни цвета, ни галочки, ни реакции. Выбранный
вариант просто подсвечивается голубым.

После выбора появляется:
`Запомним твой ответ. В конце вернёмся к этому же проекту.`

Кнопка: **Познакомиться с Васей ближе**

Ответ сохраняется в состояние под ключом `verdictFirst` и переживает
перезагрузку.

### Экран 4 — `who-is-vasya`

Четыре карточки, горизонтальный свайп с индикатором позиции. Кнопка «дальше»
активна только после просмотра всех четырёх.

**Карточка 1. Это Вася**
> Он не хочет взять двадцать клиентов, получать с каждого по десять тысяч и
> круглосуточно отвечать на сообщения: «А что там с рекламой?»
>
> Он хочет иметь три-пять нормальных проектов, давать там более сильный
> результат и получать за каждый больше денег.

**Карточка 2. Это тоже Вася**
> Он уже умеет настраивать рекламу.
>
> Ему не нужен ещё один урок о том, как добавить минус-слова или выбрать
> стратегию.
>
> Он хочет понять, что ему добавить к своей работе, чтобы перестать выглядеть
> как ещё один человек, который умеет пользоваться рекламным кабинетом.

**Карточка 3. И это Вася**
> Когда продаж нет, он не хочет бесконечно перебирать одни и те же рычаги.
>
> Почистить площадки. Ещё раз посмотреть запросы. Переписать объявления.
> Поменять стратегию. Вернуть всё обратно. Снова переписать объявления.
>
> Он хочет понимать, где именно находится проблема.

**Карточка 4. И, возможно, Вася — это ты**
> Он не хочет становиться директором по маркетингу, программистом, дизайнером
> и копирайтером одновременно.
>
> Но он хочет уметь достаточно, чтобы реально влиять на результат своей
> рекламы и не зависеть от каждого косяка клиента.

### Экран 5 — `wants`

Заголовок: **Что из этого сейчас больше всего про тебя?**
Подпись: `Можно выбрать несколько`

- Хочу понимать, где теряются продажи
- Хочу увеличить чек
- Не хочу брать больше клиентов
- Хочу сильнее влиять на результат
- Хочу перестать зависеть от сайта клиента
- Хочу отличаться от обычных настройщиков

После первого выбора: `Супер. Именно с этим и будем работать.`
Кнопка: **Начать разбор дела Васи** — активна минимум при одном выборе.

Сохраняется в `wants: string[]`.

### Экран 6 — `clue1-video`

Метка: `УЛИКА 01 / 03`
Заголовок: **КОГО МЫ ПРИВЕЛИ?**
Слот видео (см. §5).
Подпись под слотом: `Дело Васи. Часть первая: кому мы вообще продаём.`
Кнопка: **Осмотреть подозреваемых**

### Экран 7 — `clue1-suspects`

Вводный текст:
> Ниша — ремонт квартир. Пять человек оставили заявку. Все ввели целевой
> запрос. Все поговорили с менеджером.
>
> **На кого поставишь бюджет?**

Пять карточек-досье, в каждой имя и одна строка ситуации:

| Имя | Строка |
|---|---|
| Илья | новостройка, ипотека и аренда |
| Стёпа | вторичка и непонимание объёма работ |
| Коля | ключи через полгода |
| Саша | нужен недорогой косметический ремонт |
| Федя | квартира под реновацию |

Выбор один. После выбора — штамп `ВЕРСИЯ ПРИНЯТА` и кнопка **Разобрать дело**.
Правильных и неправильных ответов не показываем.

Сохраняется в `suspectPick`.

### Экран 8 — `clue1-debrief`

Пять досье раскрываются по очереди (аккордеон, открыт один за раз). Поля
каждого: `Ситуация`, `Причина купить сейчас`, `Что мешает`, `Готовность`.

**Илья — новостройка, ипотека и аренда**
- Ситуация: взял квартиру в новостройке, платит ипотеку и продолжает снимать жильё.
- Причина купить сейчас: каждый месяц без ремонта стоит ему аренды. Срок для него дороже скидки.
- Что мешает: боится растянутого ремонта и сдвига сроков.
- Готовность: высокая.

**Стёпа — вторичка и непонимание объёма работ**
- Ситуация: купил вторичку, не понимает, что под обоями и надо ли менять проводку.
- Причина купить сейчас: пока не сформулирована. Сначала ему нужно понять объём и цену.
- Что мешает: боится, что смета вырастет вдвое по ходу работ.
- Готовность: средняя. Ему нужен замер и честный расчёт, а не «ремонт под ключ».

**Коля — ключи через полгода**
- Ситуация: дом сдаётся через полгода, ключей ещё нет.
- Причина купить сейчас: её нет. Собирает информацию заранее.
- Что мешает: физически нечего ремонтировать.
- Готовность: нулевая сейчас, высокая через полгода. Это не отказ, это не тот месяц.

**Саша — недорогой косметический ремонт**
- Ситуация: сдаёт квартиру, нужен быстрый косметический ремонт под следующего арендатора.
- Причина купить сейчас: квартира простаивает.
- Что мешает: не готов платить за то, чего арендатор не заметит.
- Готовность: высокая, но бюджет маленький. Для дорогого ремонта под ключ это не клиент.

**Федя — квартира под реновацию** *(акцент `--alarm`)*
- Ситуация: дом в программе реновации, квартиру, скорее всего, снесут.
- Причина купить сейчас: её нет и не будет.
- Что мешает: смысл. Вкладываться в квартиру, которой не станет, незачем.
- Готовность: нулевая. При этом запрос целевой, объявление подходящее, с менеджером говорил вежливо.

## 6. Состояние

`src/store/case.ts`, zustand с `persist` в `localStorage`, ключ `case-vasya-v1`.

```ts
interface CaseState {
  step: number;               // текущий шаг маршрута, 0..23
  maxStep: number;            // максимально достигнутый
  verdictFirst: string | null;   // id варианта с экрана 3
  wants: string[];               // id вариантов с экрана 5
  suspectPick: string | null;    // id подозреваемого с экрана 7
  verdictSecond: string | null;  // id варианта с экрана 22
  cluesFound: number;            // 0..3
}
```

Действия: `goNext()`, `goBack()`, `setVerdictFirst(id)`, `toggleWant(id)`,
`setSuspect(id)`, `setVerdictSecond(id)`, `findClue(n)`, `reset()`.

Правила: `goNext` не выходит за границу маршрута; `maxStep` только растёт;
повреждённое или устаревшее содержимое `localStorage` не роняет приложение —
состояние молча сбрасывается к начальному.

## 7. Технические требования

- React 19, TypeScript строгий, Vite 6, Tailwind 4, `motion`, `zustand`.
- Без `any` нигде, кроме `src/lib/telegram.ts` — единственной границы с
  внешним SDK.
- Весь текст живёт в `src/content/*`, компоненты текст не содержат.
- Единственный файл, обращающийся к `window.Telegram` — `src/lib/telegram.ts`.
  Вне Telegram все вызовы — безопасные заглушки, приложение работает в обычном
  браузере.
- Экран — тонкий компонент поверх переиспользуемой механики. Файл больше 200
  строк — повод разделить.
- Целевая ширина 360–430px. Проверять на 360px: горизонтальной прокрутки быть
  не должно нигде.
- Безопасные зоны: `env(safe-area-inset-bottom)` под нижней кнопкой.
- Никаких внешних запросов в рантайме: шрифты самохостом, изображений нет.
- `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build` — все
  зелёные до выкладки.

## 8. Выкладка

GitHub Pages из Actions, репозиторий `PavlushaPavel/meat2`, ветка `main`.

`dist/index.html` копируется в `dist/404.html` — иначе прямой заход по пути
даёт 404.
