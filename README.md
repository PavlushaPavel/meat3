# КТО УБИЛ ПРОДАЖУ?

Telegram Mini App — воронка-расследование на 24 экрана. Дело Васи: почему
нормальный трафик не превращается в продажи и какие части связки специалист
может забрать под контроль.

Живой адрес: https://pavlushapavel.github.io/meat2/

## Документы

| Файл | Что внутри |
|---|---|
| `docs/SPEC.md` | Канон: дизайн-система, маршрут, весь копирайт по экранам |
| `docs/PLAN.md` | Разбивка работ и контракты между частями кода |
| `PRODUCT.md` | Продуктовая правда: аудитория, обещание, ограничения |
| `DESIGN.md` | Дизайн-система, записанная с построенного мира |

Правки текста воронки делаются в `src/content/*`. В компонентах текста нет —
это правило, а не совпадение.

## Разработка

```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck
npm run test
npm run lint
npm run build
```

Приложение работает и вне Telegram: обёртка `src/lib/telegram.ts` вне
мессенджера превращается в безопасные заглушки, поэтому воронку можно
проходить в обычном браузере.

## Что подставить, когда появится

Ничего из этого не требует правки кода — только переменные репозитория
(Settings → Secrets and variables → Actions → Variables). Пустая переменная
даёт честное состояние «материала пока нет», а не битую ссылку и не белый
экран.

| Переменная | Куда попадает |
|---|---|
| `VITE_VIDEO_1_URL` | видео первой улики: кого мы привели |
| `VITE_VIDEO_2_URL` | видео второй улики: что мы ему пообещали |
| `VITE_VIDEO_3_URL` | видео третьей улики: куда мы его привели |
| `VITE_ASSISTANT_AUDIENCE_URL` | кнопка «Забрать ассистента» после первой улики |
| `VITE_ASSISTANT_OFFER_URL` | кнопка «Забрать ассистента» после второй улики |
| `VITE_CHECKOUT_URL` | кнопка «Забрать третий рычаг», оплата практикума |
| `VITE_SUPPORT_URL` | ссылка на поддержку на последнем экране |

После изменения переменной запустить workflow Deploy заново — сборка
подставит значения.

Кадры Васи: компонент `VasyaScene` принимает проп `frameSrc`. Пока он не
задан, персонаж рисуется CSS-сценой. Появятся настоящие кадры — они встанут
на то же место, композиция вокруг не меняется.

## Выкладка

GitHub Actions → GitHub Pages, ветка `main`. Workflow прогоняет типизацию,
тесты и линтер, и только потом собирает. `base` задаётся флагом сборки в
workflow, а не в `vite.config.ts`: путь публикации — свойство деплоя, а не
исходников. `index.html` копируется в `404.html`, иначе прямой заход по
внутреннему пути даёт 404.
