# Сад обратной гравитации

Telegram Mini App — воронка-прогрев для перформанс-маркетологов. 14 экранов,
которые доводят специалиста от «клиент говорит, что заявки говно» до покупки
практикума «Лендос за вечер».

Воронка меняет картину мира в три шага: качество заявки формируется до
рекламного кабинета → правильного человека можно самому сделать холодным
слабым сообщением → и вся логика умирает после клика, если посадочная её не
продолжает.

Живой адрес: https://pavlushapavel.github.io/meat3/

## Документы

| Файл | Что внутри |
|---|---|
| `PRODUCT.md` | Продуктовая правда: аудитория, обещание, что запрещено выдумывать |
| `docs/SPEC.md` | Канон: мир, маршрут из 14 шагов, механики, восемь запретов |
| `DESIGN.md` | Дизайн-система, записанная с построенного мира |
| `index.html` | Контракт направления — HTML-комментарием, переживает прод-сборку |

## Где что лежит

- **Весь текст воронки — в `src/content/*`.** В компонентах копирайта нет, это
  правило канона, а не совпадение. Правки текста делаются только там.
- Механика мира — `src/mechanics/*`: детерминированное векторное поле на
  canvas, четыре закона гравитации, капля-сообщение.
- Кит — `src/ui/*`: таблетка с каплевым столбцом, две поверхности, гнутый
  заголовок через SVG textPath, чёрный цветок, орбита рычагов.
- Экраны — `src/features/*`, маршрут — `src/router/flow.ts`.

## Разработка

```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck
npm run test
npm run lint
npm run build
```

Приложение работает и вне Telegram: обёртка `src/lib/telegram.ts` вне
мессенджера превращается в безопасные заглушки, поэтому воронку можно
проходить в обычном браузере.

## Что подставить, когда появится

Ничего из этого не требует правки кода — только переменные репозитория
(Settings → Secrets and variables → Actions → Variables). **Пустая переменная
даёт честное рабочее состояние**, а не битую ссылку и не белый экран: слот
видео говорит «материал пока не подключён», кнопка становится пунктирным
контуром с подписью. Воронка проходима до конца при полностью пустом
окружении — это её текущее состояние.

| Переменная | Куда попадает |
|---|---|
| `VITE_VIDEO_1_URL` | Видео 1 «Кому мы продаём» |
| `VITE_VIDEO_2_URL` | Видео 2 «Офферы и формулы» |
| `VITE_VIDEO_3_URL` | Видео 3 «Лендос за вечер» |
| `VITE_ASSISTANT_AUDIENCE_URL` | Кнопка «Забрать ассистента» после первого видео |
| `VITE_ASSISTANT_OFFER_URL` | Кнопка «Забрать ассистента» после второго видео |
| `VITE_CHECKOUT_URL` | Оплата практикума за 3 990 ₽ |
| `VITE_SUPPORT_URL` | Поддержка на последнем экране |

После изменения переменной запустить workflow Deploy заново — значения
подставляются на сборке.

## Выкладка

GitHub Actions собирает и **публикует пушем в ветку `gh-pages`**; источник Pages
в настройках репозитория стоит на этой ветке. Workflow прогоняет типизацию,
тесты и линтер, и только потом собирает. `base` задаётся флагом сборки в
workflow, а не в `vite.config.ts`: путь публикации — свойство деплоя, а не
исходников. `index.html` копируется в `404.html`, иначе прямой заход по
внутреннему пути даёт 404.

### Почему не через `actions/deploy-pages`

06.08.2026 у GitHub одновременно встали оба конвейера, и это стоило нескольких
часов. Симптомы и разбор, чтобы не выяснять заново:

- **Задание отменяется через ~15 минут, не выполнив ни одного шага, раннер не
  назначен.** Значит, свободных раннеров нет. Не квота: для публичных
  репозиториев Actions бесплатны. Лечится только ожиданием или повтором.
- **`Timeout reached, aborting!` на шаге деплоя.** Артефакт собран и загружен,
  но очередь Pages не забрала его за десять минут. Десять минут — жёсткий
  потолок `actions/deploy-pages`, поднять нельзя: большее значение обрезается
  предупреждением `timeout value is greater than the allowed maximum`.
- **`Deployment cancelled` или `due to in progress deployment` на следующей
  попытке.** Отменённый по таймауту деплой блокирует новые: его идентификатор
  равен хэшу коммита. Снимается запросом
  `POST /repos/PavlushaPavel/meat3/pages/deployments/<sha>/cancel`, после чего
  нужен новый коммит.

Пуш в ветку убирает из цепочки очередь Pages-деплоя — остаётся одна
зависимость вместо двух. Если понадобится вернуться на прежнюю схему: заменить
шаг публикации на `configure-pages` + `upload-pages-artifact` + `deploy-pages`,
вернуть разрешения `pages` и `id-token` и переключить источник Pages на
GitHub Actions.

### Аварийная выкладка руками

Когда раннеры недоступны, сайт можно опубликовать со своей машины — Actions
для этого не нужны совсем:

```bash
npm run build -- --base=/meat3/
cp dist/index.html dist/404.html && touch dist/.nojekyll
cd dist && git init -q && git checkout -q -b gh-pages
git add -A && git commit -q -m "Выкладка вручную"
git push -f https://github.com/PavlushaPavel/meat3.git gh-pages
```
